3 What to improve — ranked by how often it came up

Satisfaction was high, but four suggestions recurred. They are listed most-mentioned first, each with a concrete fix.

1 Most frequent

More hands-on practice top request

Participants consistently asked for more implementation exercises, practical activities, time to experiment, and guided practice.

  • Need more time
  • Implementation part could be improved
  • More hands-on activities
  • Maybe a Version 2 workshop
Fix: reduce lecture time, add live step-by-step exercises, and reserve at least 40–50% of each session for hands-on work.
2 Frequent

Share learning materials afterward

Participants wanted slides, reference materials, cheat sheets, and documentation to revisit later.

  • Share presentation slides
  • Provide an n8n cheat sheet
  • Share reference materials
Fix: send a resource package after every session — slides, cheat sheet, useful links, sample projects, FAQs.
3 Recurring

Better pre-workshop preparation

Several participants hit setup issues. Prerequisites, software versions, and dependencies should arrive earlier.

  • Include Node.js version
  • Include package dependencies
  • Let us set up beforehand
Fix: send a pre-workshop checklist 2–3 days ahead — required software, versions, install guide, accounts, sample files.
4 Occasional

Match the pace to the room

Some participants needed more time to absorb technical demonstrations.

Fix: slow down during demos, pause for questions after each major section, and add short recaps before moving on.

4 The story in one view: keep vs change

This is the slide to linger on — what stays, and what changes for the next round of workshops.

Keep — proven strengths

  • Clear explanations and friendly facilitation
  • Real-world examples and relevant use cases
  • Organized agenda and interactive demonstrations
  • Practical content tied to daily work

Change — the four fixes

  • More hands-on: 40–50% of every session is practice
  • Materials after: slides + cheat sheets + samples
  • Setup before: checklist 2–3 days in advance
  • Steadier pace: pauses and recaps built in

5 The playbook: Before · During · After

The fixes above collapse into one repeatable checklist for every future facilitator.

Before
  • Share prerequisites & install guide
  • List software versions & dependencies
  • Confirm setup is done beforehand
  • Send the agenda in advance
During
  • Explain concepts clearly
  • Demo practical, real-world examples
  • Prioritize hands-on activities
  • Leave time for Q&A & troubleshooting
  • Pace for mixed skill levels
After
  • Share slides & cheat sheets
  • Share sample projects / source code
  • Include docs & learning resources
  • Consider a “Part 2” follow-up

The ask for this team

The workshops were highly successful — the opportunity now is to shift from information delivery toward interactive, hands-on learning. Next step: adopt the Before · During · After checklist as the standard for every future workshop, starting with the 40–50% hands-on rule.
